# How we review pull requests in 15 minutes

*Published: 2026-02-01*

Short feedback cycles keep teams moving. Our process is simple:

1. Start with the problem statement and expected outcome.
2. Scan for risky changes in state, security, and data boundaries.
3. Confirm tests cover behavior changes, not only implementation details.
4. Leave actionable comments with suggested code snippets.

## Review checklist

- Is the intent obvious from title and description?
- Are edge cases covered?
- Can we observe failures quickly in production?

Fast reviews are less about speed and more about consistency.
