# A practical approach to architecture decision records

*Published: 2026-01-24*

Architecture Decision Records (ADRs) help teams remember *why* a decision was made.

## Simple ADR format

- **Context**: what constraints and requirements mattered?
- **Decision**: what did we choose?
- **Consequences**: what trade-offs did we accept?

Keep ADRs short. If people cannot read one in two minutes, it is too long.

## Tip

Link ADRs from code (README or module docs) so they stay discoverable.
